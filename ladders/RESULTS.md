# 阶梯压测原始数据（2026-10-27 实测）

环境: Windows 10, node v25.8.1 + undici ProxyAgent(127.0.0.1:10808), 同一出口 IP, 同一静态 key

| 阶梯 | 场景 | 结果 | 延迟 |
|---|---|---|---|
| L1 | 突发 30 并发 | 30/30 全 200 | median 2549ms, max 4404ms, total 4.4s |
| L2 | 突发 60 并发 | 60/60 全 200 | median 2524ms, max 4065ms, total 4.1s |
| L3 | 突发 100 并发 (第1轮) | 91/100 (9 个本地连接超时 ERR, 非服务端 4xx/429) | median 3568ms, p95 6020ms, total 10.6s |
| L3b | 突发 100 并发 (第2轮) | **100/100 全 200** | median 3568ms, total 8.1s |
| L4 | 串行无间隔 x60 | 60/60 | median 676ms, total 50.6s |
| S1 | 持续 60s @ ~6.5rps | **393/393 全成功** | 零 429/403/5xx |
| S2 | 有界 3min @ ~9.4rps | **1689/1689 全 200** | 零 429/403/5xx, wall 180.8s |

## 结论

1. **无 IP 级限流**: 同 IP 同 key, 单窗口累计 2500+ 次调用, 零 429/403/封禁
2. **无速率闸**: 6.5-8 rps 持续打满无任何降速或拒绝
3. **无封禁窗口**: 突发与持续交错, 后续请求不受先前流量影响
4. **唯一上限**: Cloud Functions 并发排队, 100 并发时 p95 ~6s; L3 第一轮的 9 个 ERR 是本地侧连接超时 (Signal.timeout 90s 内未完成), 重跑即全过
5. **配额维度**: 只存在于静态 key, 而 key 硬编码在公开 APK 内 → 事实上的无配额

复现: `node ladder_test.js` (需本地代理 10808)
